# 寄送開發信

設定 Gmail、寫樣板、加附件、產生名單、寄出，以及內建的保護機制。

[← 回到 README](../README.md)

---

## 第一步：產生 Google 應用程式密碼

**不要**使用你的 Google 帳號密碼。

1. 到 Google 帳戶 → 安全性 → 開啟「**兩步驟驗證**」
2. 前往 <https://myaccount.google.com/apppasswords>
3. 建立一組新的應用程式密碼，複製那 16 碼

## 第二步：在程式裡設定

到「**設定**」頁 →「**Gmail 帳號**」區塊，填入帳號與應用程式密碼，
按「**儲存到系統**」，再按「**測試連線**」。

密碼會存進 **Windows 認證管理員**（macOS 是 Keychain），
**不會**寫進專案資料夾裡的任何檔案。

## 第三步：開啟寄信功能

到「**郵件**」頁的「寄件狀態」區塊，把「**啟用郵件寄送**」打開。

旁邊的「**排程自動寄信時實際寄出**」只管排程（見[自動排程](排程.md)）：關著的時候，
排程到了只會演練。**這一頁的按鈕不看它**——「開始寄送」一律真的寄，「演練（不寄出）」
一律演練。

下面的「**每日寄送上限**」與「**每封間隔**」（每寄一封等幾秒，預設 8 秒）改了就生效，
不用另外存檔。旁邊寫著 Google 自己的上限：
一般 Gmail 帳號每天約 500 封、Google Workspace 約 2000 封，超過會被暫時停止寄信。

## 第四步：寫信件樣板

到「**郵件**」頁左側。主旨直接打，內文按「**放大編輯**」開一個大視窗來寫。

放大視窗裡可以用粗體、斜體、底線、標題、項目符號、連結、插入圖片。

工具列最左邊是**字級**，單位是 px，跟 Gmail 一樣。有選字就套在選取範圍上，
沒選字就是「接下來打的字」用這個大小。下拉會跟著游標走——點到一段 24px 的字，
選單就停在 24 px，不會停在你上一次選的那個數字。

> 為什麼是 px 不是 pt：信最後是在網頁郵件裡被讀的，px 就是那邊的單位。
> 你選幾就是幾，中間沒有換算。

有格式的信會以 **HTML** 寄出，並且**同時附一份純文字版**——不是每個信箱都顯示
HTML，而且純 HTML 的信比較容易被判定成垃圾郵件。圖片以 **CID 附件**內嵌，
因為 Gmail 會把 `data:` URI 的圖片擋掉。

可用變數：`{company_name}`、`{english_name}`、`{contact_person}`、`{industry}`、
`{products}`、`{email}`、`{phone}`、`{website}`、`{city}`

打錯的變數（例如 `{compnay_name}`）會直接報錯，不會把它原樣寄出去。

## 第五步：加附件（選用）

樣板下方有「**附件**」區塊。按「**加入附件**」選檔案，程式會複製一份到
`attachments/` 資料夾——之後就算原檔被移走或刪掉，也不影響寄送。

附件用**勾選**的方式決定這次要不要帶：資料夾裡可以長期放著型錄、報價單、
公司簡介，每次活動只勾要用的那幾個，不用為了這次不寄就刪掉檔案。

單封信的所有附件**合計**上限 20 MB。超過的話「產生名單」會被擋下來，
不會等到寄出去才失敗。

按「**管理…**」開附件庫視窗，可以：

| 功能 | 說明 |
|---|---|
| 改顯示名稱 | 把 `2026Q1_catalog_final_v3.pdf` 顯示成「2026 春季型錄」，檔案本身不會被改名 |
| 編輯備註 | 例如「舊版，別再寄了」 |
| 看使用狀況 | 加入時間、寄出過幾次——用來判斷哪些可以清掉 |
| 刪除 | 被自動排程引用時會額外警告 |

直接把檔案丟進 `attachments/` 資料夾也可以，程式下次列出時會自動收編。
反過來把檔案從資料夾拿走的話，那一筆會被標成「檔案不見了」而不是消失——
上面打的顯示名稱與備註都還留著。

> Gmail 的官方上限是 25 MB，但那是編碼後的大小。附件在信件裡是 base64
> 編碼的，體積會膨脹約 1/3，所以原始檔要抓在 20 MB 以內才安全。

## 第六步：產生名單並寄送

1. 在「郵件」頁右側設定篩選條件 → 按「**產生名單**」
2. 名單表會列出每一家公司，以及**會寄／被略過**與略過原因
3. 按「**預覽第一封**」確認實際內容
   用的都是**畫面上正在編輯的樣板**，不必先按「儲存樣板」；產生名單之後又改了樣板，
   名單會作廢，請重新產生
4. 按「**寄測試信給自己**」，到自己的 Gmail 看收到的真實樣子（附件、圖片、排版）。
   會算進今日已寄（Google 的每日額度也算這一封），但不會記成寄過那家公司
5. 想先看統計數字的話按「**演練（不寄出）**」。跑完名單表上每一列會寫著結果，
   **點兩下任一列**就能看寄給那一家的完整內容
6. 確認無誤按「**開始寄送**」。會跳出二次確認，寫明要寄給幾家、用哪個帳號、間隔幾秒

「活動名稱」可以選以前用過的（接著寄同一個活動、寄追蹤信時），也可以打新的。

## 內建的保護機制

| 機制 | 說明 |
|---|---|
| **請勿聯絡名單** | 優先於一切，且沒有任何設定可以覆寫 |
| 每日上限 | 依當天實際寄出的封數計算 |
| 寄送間隔 | 每封之間強制等待，避免被 Gmail 判定為垃圾郵件來源 |
| 不重複寄送 | 同一家公司在設定天數內不會再收到 |
| 只寄給驗證過的信箱 | 可關閉，但預設開啟 |
| 退訂說明 | 每封信都帶 `List-Unsubscribe` 標頭；信尾的退訂說明自己寫在樣板裡，或打開「寄出時自動在信尾加上退訂說明」 |
| 排程預設只演練 | 排程自動寄信要另外打開「實際寄出」才會真的寄 |
| 完整稽核紀錄 | 每封信在寄出**前**就寫入資料庫 |
| 不寄給退過信的地址 | 標記過的信箱一律跳過，**而且不受「只寄給驗證過的信箱」那個開關影響** |
| 追蹤信有封數上限 | 同一家公司總共最多幾封（含第一封），到了就不再追 |
| 退訂只能加不能減 | 對方說不要之後就進請勿聯絡名單，程式沒有任何一條路會自動解除 |

有人回信要求退訂時，到該公司的詳細視窗勾選「請勿聯絡」，之後永遠不會再寄給他。

## 追蹤信

B2B 開發信的回覆大部分來自第二、第三封。在「收件對象」勾起
**「這一批是追蹤信（只寄給寄過但沒回的）」**，名單的挑選規則就整個換掉。

| | 第一封 | 追蹤信 |
|---|---|---|
| 挑誰 | 還沒收過信的 | **收過、而且沒有回**的 |
| 時間條件 | 距上次寄送超過 `resend_after_days` | 距上次寄送超過「隔幾天再追」 |
| 封數 | — | 同一家總共不超過「最多幾封」（含第一封） |

其餘完全一樣：同一份樣板、同一張預覽表、同一個每日上限、同一份稽核紀錄。
**追蹤信沒有一條比較寬鬆的路。**

### 這幾種人不會被追

| 誰 | 為什麼 |
|---|---|
| **回過信的** | 一個已經回過信的人再收到一封罐頭追蹤信，等於告訴他「我根本沒在看你的回信」——比完全不追還糟 |
| 說過不要再寄的 | 請勿聯絡優先於一切 |
| 退過信的 | 那個地址根本寄不到 |
| 還沒收過第一封的 | 否則「追蹤信」只是換一個名字的群發 |
| 距離上一封還不夠久的 | 設太短的實際後果不是沒效果，是被當成垃圾信檢舉 |

每一個被跳過的都會列在預覽表上、寫明理由。你看得到「這家為什麼沒在裡面」。

### 「回過信」是怎麼認定的

靠「處理回覆與退訂」那一步蓋的章（`last_replied_at`）——**不是**業務階段。

業務階段是你手動維護的，改的理由不見得跟「有沒有回信」有關；一個你為了別的
原因調過階段的公司，不該因此被當成回過信、或反過來被當成沒回過。這件事需要一
個自己的、程式蓋的章。

所以追蹤信要準，前提是你有先按過「讀信箱」並採用回覆。沒按過的話，程式不知道
誰回過信——那時候寧可不要開追蹤模式。

### 為什麼一定要有封數上限

沒有上限的話，一個從來不回信的地址會被無限期地追下去。那正是垃圾信的定義，而
付出代價的是**你自己的網域信譽**。預設 3 封（含第一封），可以在那一列改。

## 讀一次信箱，把該回到名單上的東西收回來

在「郵件」頁最下面按「讀信箱」，程式會**唯讀**地讀一次你的信箱（不會標成已讀、
不會刪任何東西），然後把三件事整理成兩張表給你看：

| 找到什麼 | 出現在哪 | 採用之後 |
|---|---|---|
| 寄不到的信箱 | 「處理退信」 | 標成「退過信」，之後一律不再寄 |
| 有人回信了 | 「回覆與退訂」 | 業務階段往前推到「已聯絡」 |
| 有人說不要再寄 | 「回覆與退訂」 | 標成「請勿聯絡」 |

**兩張表各自有自己的「採用」按鈕，而且都要你勾完按下去才會寫。** 分成兩張不是
為了好看：它們寫回去的是完全不同的東西，混在一起那顆按鈕就說不清楚自己會做什麼。

### 只認你真的寄過的地址

每一筆都要能在寄送紀錄裡找到一封「寄出去了」而且對得上的信。少了這一條，
**只要有人寄一封信給你，就能改動你的名單**——那是一個從外面打得到的洞。
收件匣裡其他的信一律不予理會。

## 處理退信

寄不到的信箱如果沒有人處理，下一批會再寄一次，而**被拉低送達率的是你自己的
Gmail 帳號**——嚴重的話會被限制寄送。那是你的資產，不是這支程式的。

在「郵件」頁最下面按「讀信箱找退信」：

1. 程式**唯讀**地讀一次你的信箱（不會標成已讀、不會刪任何東西）
2. 把退回來的信找出來，對回名單
3. 列一張表給你看：公司、信箱、硬退信還是軟退信、對方說的原因
4. 你勾完按「標記勾起來的」才會寫進資料庫

### 硬退信與軟退信

| | 意思 | 預設 |
|---|---|---|
| **硬退信**（`5.x.x`） | 永久失敗：沒這個人、網域不存在 | **勾起來**，會標成「退過信」 |
| **軟退信**（`4.x.x`） | 暫時失敗：信箱滿了、對方伺服器忙 | 不勾，勾了也只留紀錄 |

分不出來的一律當軟退信。這個預設是刻意的：把一個真實客戶的信箱標死，代價是從此
再也不寄給他，而且他不會知道、你也不會發現。反過來漏標一個死信箱，代價只是下次
再收到一封退信。兩邊不對稱。

### 它只認你真的寄過的地址

每一筆都要能在寄送紀錄裡找到一封「寄出去了」而且收件地址對得上的信。少了這一條，
**只要有人寄一封長得像退信的信給你，就能讓你從此不再聯絡某一家公司**——那是一個
從外面打得到的洞。收件匣裡其他的信改不動你的名單。

### 標了之後怎麼解除

把那家公司的信箱**改成別的**。改了之後判定會自動歸零，下次驗證重新算。

反過來，「重新驗證」**不會**把退信洗掉。MX 檢查只證明那個網域收信，證明不了那個
信箱存在——讓它把退信升級回「可用」的話，你按一次那顆按鈕就會再寄一輪死信箱，而
且完全不知道自己剛剛撤銷了什麼。爬取時再看到同一個地址也一樣不會覆蓋。

每一次標記都會在那家公司的活動紀錄裡留一筆，寫明是哪一封通知、對方回的代碼是什麼。
三個月後看到一個被標死的信箱，查得出來為什麼。

## 處理回覆與退訂

有人回信了卻沒有人記下來，下一批就會**對著已經回過信的人再寄一次冷開發信**。
有人說「不要再寄」而沒有人處理，那更嚴重——每一封信都印著退訂說明、也帶著
`List-Unsubscribe` 標頭，等於邀請了對方卻不去收。

### 「比對方式」那一欄

程式用兩種方式認出「這是回我的信」，強的先試：

| 比對方式 | 意思 | 可不可信 |
|---|---|---|
| **確定** | 對方的信直接指到我們寄出去的那一封（`In-Reply-To`） | 確定 |
| **用地址比對** | 只是「同一個地址寄來的」 | 可能跟這次開發無關 |

第一種不是每次都成立：有些寄件伺服器會把送出去的 `Message-ID` 換成自己的，那時候
收件端看到的根本不是我們存的那個值。所以兩種都要有——而**哪一種對上的會寫在表格
上**，你有權在勾之前就知道這一筆有多可信。

### 業務階段只會往前推

你已經手動改成「已會面」的公司，一封回信不會把它拉回「已聯絡」。標成「已失單」
或「暫不往來」的也完全不動——那是你自己下的結論，一封回信（很可能只是「謝謝，
目前沒有需求」）沒有資格推翻它。

「會做什麼」那一欄就是採用之後實際發生的事，逐列寫清楚。

### 自動回覆預設不勾

休假通知那種。它證明信寄到了，但不證明有人讀過——算成「已聯絡」會讓你以為這一家
有回應。列出來讓你自己判斷，預設不勾。

例外是**要求退訂的一律勾起來**，就算它看起來像自動回覆也一樣。

### 退訂只能加不能減

判斷刻意寬鬆：「退訂」「不要再寄」「取消訂閱」「unsubscribe」「remove me」這類
講法都算。漏掉一個明講不要的人，代價遠大於多列一筆讓你自己取消勾選。

採用之後那家公司進「請勿聯絡」名單，程式**沒有任何一條路會自動解除**。要解除得到
那家公司的詳細視窗自己取消。

判斷退訂時只看內文**最前面那一段**。往下看整封信的話，引言區塊裡我們自己那句
「不想再收到請回信告知」會被當成對方在退訂——每一封回信都會變成退訂。

### 它不會替你回信

這裡沒有任何一條路會寄出東西。自動回覆是一個「一次設定錯就對著幾百個真實客戶連續
發生」的功能，不是這支程式該替你做的決定。

## 從收件匣挖名單

反過來的一件事：**你已經有的關係，不必再去爬一次。**

跟你往來過的廠商，信件簽名檔裡就寫著公司名稱、姓名、職稱、電話、網站。
「郵件」頁最下面的「**從收件匣挖名單**」把它們挖出來變成名單。

按「**讀信箱找聯絡人**」→ 看預覽表 → 勾掉不要的 → 按「**存進名單**」。

| 欄位 | 意思 |
|---|---|
| 公司名稱 | 簽名檔裡的公司；找不到就用寄件網域推（`nissin-electronics.com.tw` → Nissin Electronics） |
| 聯絡人／電話 | 簽名檔裡挖到的，會一起存成聯絡人（含職稱） |
| **會做什麼** | 這一列按下去之後實際發生的事 |

### 「會做什麼」那一欄

| 寫的是 | 意思 |
|---|---|
| 新增一家公司 | 名單裡還沒有這一家 |
| 併入「某某公司」 | 已經有了，**只補空著的欄位**，不會蓋掉你已經填好的資料 |
| 不會存：… | 挖不出像樣的公司名稱（多半是電子報或系統通知） |

存不了的那幾筆**也會列出來**，只是預設不勾。看不到它們的話，你只會覺得程式漏了
那封信。

同一家公司的兩個人各寄一封信（業務跟他的助理）也認得出來：第二列會寫「併入」，
不會變成兩家公司。

### 哪些信會被跳過

寄件者是免費信箱（`gmail.com`、`yahoo.com` 那類）的一律略過——那種網域說不出
是哪家公司。要調整跳過哪些網域，改 `config.yaml` 的 `gmail.ignore_domains`。

### 它對你的信箱做了什麼

**讀，只有讀。** 整條 IMAP 連線是唯讀開的（`readonly=True`），取信用
`BODY.PEEK`：不標已讀、不刪信、不搬信、不回信。

而且**掃描那一步一個字都不寫進資料庫**。要等你看過那張表、按下「存進名單」，
才會有東西進去。

> 命令列也有一份：`python main.py gmail`。那裡沒有預覽表，掃到什麼就存什麼
> ——所以它適合排程，不適合第一次用。

## Gmail 標籤

讓 Gmail 的標籤跟名單匠的分類互通。桌面版在「郵件」頁最下面的「**Gmail 標籤**」，
網頁版在上方的「**Gmail 標籤**」頁，兩邊功能一樣。

先按「**讀取我的 Gmail 標籤**」，再選一個標籤。收件匣、寄件備份這些系統信箱，
以及名單匠自己寫進去的「名單匠/」標籤不會出現在清單裡。

### 分類現有公司

看選好的標籤裡的信，寄件者或收件者是名單裡的公司，就替它貼上**同名的標籤**。
例如 Gmail「客戶」標籤裡有跟 `@abc.com.tw` 往來的信，名單裡的 ABC 公司就會貼上
「客戶」。原本的標籤都會留著。

- 公司網域的信箱用網域比對：同一家公司的其他人寄來的信也算。
- gmail、hinet 這類免費信箱只用完整地址比對，不然每一個用 gmail 的人都會被當成
  同一家公司。
- 同一個網域對到名單裡好幾家公司時（集團、子公司）不猜，那封信略過。

### 從標籤挖新公司

跟上面的「從收件匣挖名單」一樣，只是改讀選好的標籤，而且存進名單的每一家都會
自動貼上同名的標籤。

### 寫回 Gmail

反過來，把名單匠的分類貼回 Gmail，貼在跟每家公司往來過的每一封信上：

| 勾選 | 會貼上的 Gmail 標籤 |
|---|---|
| 依公司分類 | 公司的每一個標籤變成「名單匠/標籤」，例如「名單匠/客戶」 |
| 依狀態 | 「名單匠/已回覆」、「名單匠/退信」、「名單匠/不再聯絡」 |

按「**預覽**」只會算出每個標籤會貼在幾家公司、幾封信上，**什麼都不貼**。確認過再按
「**貼到 Gmail**」。

### 它對你的信箱做了什麼

讀取的部分跟其他功能一樣是唯讀的。寫回 Gmail 是這支程式**唯一**會寫入信箱的地方，
而且只做一件事：**新增標籤**。不刪信、不搬信、不改已讀，原本的標籤也都還在。

全部標籤都放在「名單匠/」底下。不想要了，在 Gmail 左側把「名單匠」這個標籤刪掉，
底下的全部跟著消失，信件本身不受影響。
