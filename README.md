# 名單匠 Roster

蒐集**公開**的台灣 B2B 廠商聯絡資料，清理、驗證、建檔、匯出，
並可透過你自己的 Gmail 寄送開發信。

Python 3.12+ ｜ 桌面應用程式（PySide6）｜ 本機 SQLite ｜ Windows / macOS / Linux ｜ 也可用命令列操作

最新版本 **v1.6.1** — 這一版改了什麼見 [`CHANGELOG.md`](CHANGELOG.md)

> **使用前請先閱讀本文件最後的[免責聲明](#免責聲明)。**
> 本工具僅供蒐集網站公開顯示的商業聯絡資訊，使用者須自行確認每一個爬取目標的合法性並自負全部責任。

## 安裝

需要 **Python 3.12 或更新版本**（[官方下載](https://www.python.org/downloads/)。
Windows 安裝時記得勾選 *Add python.exe to PATH*）。

打開你的作業系統對應的資料夾，**雙擊「安裝」**，剩下的它會自己做完：

| 你的系統 | 打開這個資料夾 | 雙擊 |
|---|---|---|
| Windows | `Windows/` | `安裝.bat` |
| macOS | `macOS/` | `安裝.command` |
| Linux | `Linux/` | `./install.sh` |

安裝程式會建立虛擬環境、下載套件（約 150 MB，需要幾分鐘），
macOS 還會順便產生 `Roster.app`。可以重複執行，已經裝好的部分會直接跳過。

### 日常啟動

| | Windows | macOS | Linux |
|---|---|---|---|
| 開啟程式 | `Windows/啟動.bat` | `macOS/啟動.command` 或 `Roster.app` | `Linux/start.sh` |
| 命令列 | `Windows/命令列.bat` | `macOS/命令列.command` | `Linux/console.sh` |

#### macOS 出現「Apple 無法驗證是否為惡意軟體」

macOS 會替**所有**從瀏覽器下載的檔案貼上隔離標記，沒有付費的 Apple 開發者
簽章就一律顯示這個訊息。macOS 15 (Sequoia) 起，以前那個「按右鍵 →『打開』」
的做法已經被 Apple 拿掉，右鍵沒有用。

**一行指令解決**（終端機）：

```bash
xattr -dr com.apple.quarantine ~/Desktop/Roster
```

路徑換成你資料夾實際的位置——打完 `com.apple.quarantine` 留一個空白，
再把資料夾拖進終端機視窗，路徑會自動填好。之後雙擊就正常了。

**或者一開始就用 git 下載**，clone 下來的檔案不算「從網路下載」，不會被貼
標記，下載完直接雙擊就能用：

```bash
git clone https://github.com/WayneLY-Chen/Roster.git
```

安裝程式跑完會自動解除整個資料夾的隔離標記，所以只要能讓「安裝.command」
執行一次（上面任一種方法），之後的啟動都不會再被擋。
`macOS/開不起來 請先看這個.txt` 裡有同樣的說明。

> `Roster.app` 是 `macOS/建立App.command` 產生的，只是一層薄殼——執行時仍然
> 使用專案資料夾裡的 `.venv`，所以改了程式碼不用重新產生，代價是它不能單獨
> 搬到別台電腦。要那樣的話得用 PyInstaller 打包（設定檔是
> `packaging/roster.spec`）。

### 爬 JavaScript 網站才需要的額外步驟

只有要爬「用 JavaScript 動態產生內容」的網站時，才需要多裝一次瀏覽器。
開啟命令列之後執行：

```bash
python -m playwright install chromium
```

### 搬動資料夾

啟動腳本都以自己所在的位置推算路徑，整個資料夾搬到哪裡、改成什麼名字都能用。

> 如果搬動之後 `pip`、`pytest` 這些指令失效，那是 Python 虛擬環境本身
> 不可搬移的已知行為。改用 `python -m pip`、`python -m pytest` 即可，
> 或重新執行一次安裝檔。

## 五分鐘上手

### 先確認整條流程正常（不用連網）

1. 依上方步驟建好環境，啟動程式
2. 到「**匯入**」頁 → 按「**下載範例檔**」→ 存成 Excel
3. 打開那個檔案，第二個分頁有逐欄說明。照著填幾家公司，存檔
4. 回到「**匯入**」頁 → 「選擇檔案…」選它 → 確認欄位對應 → 按「**匯入**」
5. 到「**公司**」頁看資料，再到「**匯出**」頁匯出來對一次

這一輪完全不會連到任何網站，用來確認安裝沒問題。

### 開始爬第一個名錄

1. 到「**爬取**」頁 → 按「**＋ 自訂網址…**」
2. 貼上你有權限爬取的名錄網址 → 按「**分析網頁**」
3. 程式會告訴你抓到幾筆、有哪些欄位、這個名錄總共幾頁
4. 在「預覽抓到的資料」確認內容 → 填來源名稱 → 「**儲存並立即爬取**」

程式**不預先附任何爬取來源**——要爬哪些網站是你自己的決定，
而且你必須先確認那個網站允許被爬取（見文末的[免責聲明](#免責聲明)）。

## 每一頁在做什麼

| 頁面 | 用途 |
|---|---|
| **儀表板** | 總覽：公司總數、信箱數、本週新增、疑似重複、業務階段分佈、最近爬取紀錄 |
| **公司** | 主要工作區。搜尋、篩選（含依收集日期）、新增、編輯、刪除、找出重複並合併 |
| **聯絡人** | 跨公司搜尋所有具名聯絡人 |
| **爬取** | 執行爬取、選擇要收集哪些欄位、貼網址建立自訂來源、補抓信箱、重新驗證 |
| **匯入** | 從 CSV / Excel / JSON 匯入既有名單，附範例檔下載 |
| **匯出** | 匯出 Excel / CSV / JSON，可挑欄位、下篩選條件 |
| **郵件** | 編輯信件樣板、加附件、產生收件名單、預覽、寄送 |
| **日誌** | 依分類查看執行紀錄（爬取／資料庫／匯出／介面／錯誤） |
| **設定** | Gmail 帳號、自動排程、外觀、設定總覽、備份與還原 |
| **更新資訊** | 這一版改了什麼（內容就是 [`CHANGELOG.md`](CHANGELOG.md)） |
| **反饋** | 直接在程式裡把問題回報給作者，可附截圖 |

## 爬取一個網站

### 用精靈（推薦，不用寫任何設定）

1. 到「**爬取**」頁，按「**＋ 自訂網址…**」
2. 貼上目標名錄的網址，按「**分析網頁**」
3. 程式會自己看懂那一頁的結構，並告訴你找到幾筆、抓得到哪些欄位、有沒有下一頁
4. 在「**預覽抓到的資料**」看看內容對不對
5. 填「來源名稱」→ 按「**儲存來源**」或「**儲存並立即爬取**」

**正常情況只要這五步。** 網頁怎麼解析、CSS 選擇器是什麼，都不用管。

舊式的公會名錄（整頁只有表格、沒有一個 class、內容是 Big5）也在支援範圍內：
編碼會自動偵測，「負責人︰」「營業範圍︰」這種寫在文字裡的欄位會被讀出來，
程式沒有對應欄位的（「會員代表」「入會年月日」）則照原名保留。

儲存後這個來源會出現在「來源」下拉選單，之後可以重複使用，也可以被排程自動執行。
設定存在 `custom_sources.yaml`。

### 每個來源自己的收集設定

打開精靈的「**進階設定**」，最上面幾項是**這個來源自己的設定**，存起來之後
每次爬它都會套用——包括自動排程去爬的時候：

| 設定 | 說明 |
|---|---|
| 從第幾頁開始 / 到第幾頁 | 常用的頁數範圍 |
| **這個來源的產業** | 名錄幾乎都是一個分類一頁，分類本身就是產業。但它寫在麵包屑或頁面標題裡、不在每一列的資料中，逐列抓的規則抓不到它——填在這裡就會自動補上（頁面自己有寫產業時不會被覆蓋） |
| **要收集哪些欄位** | 沒勾的欄位在寫入資料庫前會被清空。只想要公司名稱與信箱時，多抓的地址與統編只是雜訊，還會讓「尋找重複」多出無謂的比對維度 |

公司名稱不在勾選清單裡：它是必填的，不收集就等於整筆不要。

> 「爬取」頁上的起始頁／結束頁／最多幾頁是**這一次執行**的臨時覆寫，
> 留空就照來源自己的設定跑。寫在那一頁的東西自動排程不會看到。

### 抓到的東西不對的時候

打開精靈最下面的「**進階設定**」（平常收起來）。裡面可以逐欄調整程式要從網頁的
哪個位置取值，也可以新增或刪除欄位。自動偵測失敗時，這一區會自己展開。

兩個值得知道的設定：

- **「下一頁」連結的位置** — 留空就只爬第一頁
- **「最多進入幾個詳細頁」** — 很多名錄的清單頁只有公司名稱，信箱與電話要**點進去**
  才看得到。這個上限設得比公司總數小的話，後面的公司就不會有聯絡資料

> 找不到重複區塊時，通常是該頁用 JavaScript 產生內容。
> 把 `config.yaml` 的 `crawler.engine` 改成 `playwright` 再試一次。

### 抓到的公司沒有信箱？

名錄不一定會公開每一家的信箱。「爬取」頁有「**補抓信箱**」：程式會逐一連到
那些**有網址但沒信箱**的公司自己的網站，找公開刊登的聯絡信箱。

每個網站都會各自檢查它自己的 `robots.txt` 並遵守請求間隔，所以會花上幾分鐘
——按下去之前會先告訴你預估時間與公司家數。

### 直接寫設定檔

在 `config.yaml` 的 `crawler.sources` 加一段：

```yaml
- name: "my_directory"
  type: "generic_html"
  enabled: true
  start_url: "https://example.com/list?page={page}"
  max_pages: 5
  list_selector: "div.company-card"
  pagination:
    type: "query"            # query | next_link | none
  fields:
    company_name: { selector: "h3.name" }
    email:        { selector: "a[href^='mailto:']", attr: "href" }
    phone:        { selector: ".tel" }
    website:      { selector: "a.site", attr: "href" }
    address:      { selector: ".addr" }
    industry:     { selector: ".industry" }
    tax_id:       { selector: ".tax-id" }
```

每個欄位還支援 `regex`（從值裡再擷取一段）、`multiple`、`separator`。

## 整理與匯出名單

### 每一家公司會存哪些欄位

| 欄位 | 說明 |
|---|---|
| 公司名稱 | 唯一必填的欄位 |
| 英文名稱 | 台灣的公協會名錄普遍會列 |
| 統一編號 | 會檢查檢核碼 |
| 電子信箱 | 會驗證格式與收信網域 |
| 電話 / 傳真 | 會正規化（全形轉半形、去掉 +886） |
| 公司網址 / 公司地址 | 網址會自動補通訊協定；地址會抓出縣市 |
| 產業 | 名錄多半是一個分類一頁，可以在來源上設定預設值 |
| 主要產品 | 名錄上的「代理廠商及代銷產品」之類 |
| 聯絡人 | 「王小姐」「業務部 張經理」這種寫法都存得進去 |

加上業務階段、優先度、狀態、標籤、追蹤日期、備註。
在「公司」頁按「編輯」開啟詳細資料視窗即可修改，沒有資料的欄位會顯示
「（無資料）」而不是留白。

**上面裝不下的欄位不會被丟掉。** 每個名錄列的東西都不一樣——旅行公會列
「會員代表」「入會年月日」「註冊編號」，化工公會列「代理廠商及代銷產品」。
這些會照原本的名稱一起存下來，在詳細資料視窗的「其他欄位」區看得到、也能
自己新增或修改。匯出時每個各佔一欄，匯入時對應不到固定欄位的欄也收得回來。

### 資料清理

抓進來的原始文字會依序經過四關：

1. **正規化** — 全形轉半形、`+886` 電話前綴、`台`/`臺` 統一、網址補上通訊協定並移除
   `utm_*` 追蹤參數、從 `mailto:` 與「姓名 &lt;信箱&gt;」形式解出乾淨信箱
2. **驗證** — 信箱語法、拋棄式信箱網域、電話位數、網址格式、統一編號檢核碼
3. **MX 查詢** — 確認該網域是否真的收信；每個網域只查一次並快取
4. **去重**

### 去重

每筆資料會算出一把帶前綴的識別鍵，強度由高到低：

| 形式 | 依據 | 信心 |
|---|---|---|
| `tax:12345678` | 統一編號 | 精確 |
| `mail:a@b.com` | 電子信箱 | 精確 |
| `np:名稱｜電話` | 名稱＋電話 | 高 |
| `nw:名稱｜網域` | 名稱＋網站 | 高 |
| `n:名稱` | 僅名稱 | 中 |

寫入時不只比對這把鍵，還會分別用統編、信箱、名稱＋電話、名稱＋網域去找既有資料
——同一家公司可能在第 1 頁只露出電話、第 2 頁才有統編，算出來的鍵並不一樣。

**合併時只補空欄位，不會覆寫你手動整理過的內容。**

漏網之魚可以在「公司」頁按「**尋找重複**」，逐組確認後合併。

### 依收集日期檢視與整批刪除

「公司」頁的「**收集日期**」下拉選單會列出每一天各收集了幾家。你是一批一批
爬的，所以「哪一天爬的」通常比筆數區間更貼近你心裡的分組方式。

選了某一天之後，右上角的「**刪除該日全部**」會啟用——某次爬取的設定寫錯、
抓回一堆垃圾時，這是整批清掉的入口，連同底下的聯絡人、活動記錄與附件一起
刪除。選著「全部」時這顆按鈕是停用的，避免誤按清空整個資料庫。

**這個動作無法復原**，動手前建議先到「設定」頁建立一份備份。

### 匯入

「**匯入**」頁支援 CSV / Excel / JSON。旁邊有「**下載範例檔**」，
產生的 Excel 有兩個分頁：第一頁是可以直接填的空表，第二頁是逐欄說明。
填好存檔，回到「匯入」頁選這個檔案就能匯進去。

只有「公司名稱」是必填。標題可以用多種常見寫法，對應不到固定欄位的欄會照
原本的標題保留成「其他欄位」，並在匯入結果裡列出來。

### 匯出

「**匯出**」頁可以選格式（Excel / CSV / JSON）、下篩選條件、勾選欄位、
指定檔名或留空自動命名到 `output/`。

Excel 會自動凍結標題列、加上篩選、依內容調整欄寬。
CSV 預設用 `utf-8-sig`，否則繁體中文版 Excel 會把中文顯示成亂碼。

## 寄送開發信

### 第一步：產生 Google 應用程式密碼

**不要**使用你的 Google 帳號密碼。

1. 到 Google 帳戶 → 安全性 → 開啟「**兩步驟驗證**」
2. 前往 <https://myaccount.google.com/apppasswords>
3. 建立一組新的應用程式密碼，複製那 16 碼

### 第二步：在程式裡設定

到「**設定**」頁 →「**Gmail 帳號**」區塊，填入帳號與應用程式密碼，
按「**儲存到系統**」，再按「**測試連線**」。

密碼會存進 **Windows 認證管理員**（macOS 是 Keychain），
**不會**寫進專案資料夾裡的任何檔案。

### 第三步：開啟寄信功能

到「**郵件**」頁的「寄件狀態」區塊，把「**啟用郵件寄送**」打開。

旁邊還有一個「**實際寄出**」開關：

- **關著**（預設）＝演練模式。按「開始寄送」也只會寫進資料庫並標記為演練，**不會真的寄**
- **打開**＝真的寄。切換時會跳出確認，因為寄出去的信收不回來

### 第四步：寫信件樣板

到「**郵件**」頁左側。主旨直接打，內文按「**放大編輯**」開一個大視窗來寫。

放大視窗裡可以用粗體、斜體、底線、標題、項目符號、連結、插入圖片。

有格式的信會以 **HTML** 寄出，並且**同時附一份純文字版**——不是每個信箱都顯示
HTML，而且純 HTML 的信比較容易被判定成垃圾郵件。圖片以 **CID 附件**內嵌，
因為 Gmail 會把 `data:` URI 的圖片擋掉。

可用變數：`{company_name}`、`{english_name}`、`{contact_person}`、`{industry}`、
`{products}`、`{email}`、`{phone}`、`{website}`、`{city}`

打錯的變數（例如 `{compnay_name}`）會直接報錯，不會把它原樣寄出去。

### 第五步：加附件（選用）

樣板下方有「**附件**」區塊。按「**加入附件**」選檔案，程式會複製一份到
`attachments/` 資料夾——之後就算原檔被移走或刪掉，也不影響寄送。

附件用**勾選**的方式決定這次要不要帶：資料夾裡可以長期放著型錄、報價單、
公司簡介，每次活動只勾要用的那幾個，不用為了這次不寄就刪掉檔案。

單封信的所有附件**合計**上限 20 MB。超過的話「產生名單」會被擋下來，
不會等到寄出去才失敗。

按「**管理…**」開附件庫視窗，可以：

| 功能 | 說明 |
|---|---|
| 改顯示名稱 | 把 `2026Q1_catalog_final_v3.pdf` 顯示成「2026 春季型錄」，檔案本身不會被改名 |
| 編輯備註 | 例如「舊版，別再寄了」 |
| 看使用狀況 | 加入時間、寄出過幾次——用來判斷哪些可以清掉 |
| 刪除 | 被自動排程引用時會額外警告 |

直接把檔案丟進 `attachments/` 資料夾也可以，程式下次列出時會自動收編。
反過來把檔案從資料夾拿走的話，那一筆會被標成「檔案不見了」而不是消失——
上面打的顯示名稱與備註都還留著。

> Gmail 的官方上限是 25 MB，但那是編碼後的大小。附件在信件裡是 base64
> 編碼的，體積會膨脹約 1/3，所以原始檔要抓在 20 MB 以內才安全。

### 第六步：產生名單並寄送

1. 在「郵件」頁右側設定篩選條件 → 按「**產生名單**」
2. 名單表會列出每一家公司，以及**會寄／被略過**與略過原因
3. 按「**預覽第一封**」確認實際內容
4. 先按「**演練（不寄出）**」跑一次，確認統計數字合理
5. 確認無誤後把「**實際寄出**」打開，再按「**開始寄送**」
6. 會跳出二次確認，寫明要寄給幾家、用哪個帳號、間隔幾秒

### 內建的保護機制

| 機制 | 說明 |
|---|---|
| **請勿聯絡名單** | 優先於一切，且沒有任何設定可以覆寫 |
| 每日上限 | 依當天實際寄出的封數計算 |
| 寄送間隔 | 每封之間強制等待，避免被 Gmail 判定為垃圾郵件來源 |
| 不重複寄送 | 同一家公司在設定天數內不會再收到 |
| 只寄給驗證過的信箱 | 可關閉，但預設開啟 |
| 退訂說明 | 強制附加在每封信末尾，並加上 `List-Unsubscribe` 標頭 |
| 預設演練模式 | 新環境第一次跑一定是演練，不會意外寄出 |
| 完整稽核紀錄 | 每封信在寄出**前**就寫入資料庫 |

有人回信要求退訂時，到該公司的詳細視窗勾選「請勿聯絡」，之後永遠不會再寄給他。

## 自動排程

到「**設定**」頁的「**自動排程**」區塊，不需要編輯設定檔。

**可以排什麼**

| 動作 | 說明 |
|---|---|
| 只爬取 | 定時去指定的來源抓新資料 |
| 只寄信 | 定時用指定的樣板寄一批開發信 |
| 先爬取，再把名單寄出去 | 兩者依序執行 |

**多久一次**

| 頻率 | 需要填 |
|---|---|
| 每天 | 時間（24 小時制） |
| 每個月 | 幾號 ＋ 時間 |
| 每小時 | — |
| 每隔一段時間 | 間隔分鐘數 |

選「每個月 31 號」時，遇到沒有 31 號的月份會改在**當月最後一天**執行，
不會整個月跳過。

**排程寄信的設定**

選了含寄信的動作後會多出幾個欄位：

| 欄位 | 說明 |
|---|---|
| 郵件樣板 | 就是「郵件」頁左邊那些已經寫好的內容 |
| **寄給誰** | 產業、業務階段、標籤、只寄已驗證信箱——跟「郵件」頁右邊那組篩選一樣。留「全部」代表不限制 |
| 活動名稱 | 會自動接上執行日期，事後在紀錄裡分得出是哪一次跑的 |
| 隨信附件 | 從附件庫勾選 |
| 單次最多 | 這一次排程最多寄幾封 |

排程寄信走的是跟「郵件」頁完全相同的流程，所以上面那張保護機制表全部照樣生效。
另外還有一層「單次最多寄幾封」——無人看顧的批次寧可少寄、下次再寄。

> **這是桌面程式，沒有背景服務——排程只在本程式開著的時候才會執行。**
> 要不開視窗也能跑，用命令列的 `python main.py schedule`。

## 命令列

開啟命令列（`Windows/命令列.bat`、`macOS/命令列.command`、`Linux/console.sh`）之後：

```bash
python main.py --help                  # 列出所有指令
python main.py gui                     # 開啟視窗介面
python main.py crawl --list            # 列出已設定的來源
python main.py crawl -s 來源名稱        # 爬取指定來源
python main.py crawl --url URL         # 直接爬一個網址
python main.py enrich                  # 補抓信箱
python main.py verify                  # 重新驗證所有信箱
python main.py export -f excel         # 匯出
python main.py stats                   # 資料庫摘要
python main.py schedule                # 前景執行排程，Ctrl+C 停止
python main.py security                # 檢查資料安全設定
```

## 設定檔

| 檔案 | 內容 |
|---|---|
| `config.yaml` | 主設定，寫滿註解。爬取行為、驗證、匯出、寄信、排程 |
| `user_settings.yaml` | 在介面上改的設定存這裡，不會動到 `config.yaml` 的註解 |
| `custom_sources.yaml` | 用精靈建立的爬取來源 |
| `.env` | 選用。憑證優先存進系統的憑證保管庫，這裡只是後備 |

| 資料夾 | 內容 |
|---|---|
| `data/` | SQLite 資料庫 |
| `output/` | 匯出的檔案 |
| `attachments/` | 信件附件 |
| `templates/mail/` | 信件樣板與內嵌圖片 |
| `backups/` | 自動與手動備份 |
| `logs/` | 執行紀錄 |

**備份**：「設定」頁可以隨時建立備份、還原、或刪除不要的備份。每日與每週備份
會依保留數量自動清理，手動備份則會一直留著。

**資料庫加密**：`config.yaml` 的 `database.encrypt` 開啟時，信箱、電話、地址、
聯絡人姓名等個資欄位會以 AES-GCM 加密存放，金鑰放在系統的憑證保管庫。
換電腦前記得到「設定」頁「**備份金鑰**」，否則資料無法解密。
